GitHub Pages setup
==================

STEP 1 — put the workflow in place
----------------------------------
I could not write into .github/workflows/ directly (files there run code in CI,
so remote writes to that folder are blocked). Move it yourself:

  In this folder, create:   .github\workflows\
  Move into it:             github-pages-workflow.yml
  Rename it to:             deploy.yml

  Final path:
  C:\Users\fengh\Desktop\Profolio\.github\workflows\deploy.yml

  In PowerShell, from this folder:
    mkdir .github\workflows -Force
    Move-Item github-pages-workflow.yml .github\workflows\deploy.yml
    Remove-Item SETUP-GITHUB-PAGES.txt

STEP 2 — pick your repo name
----------------------------
A) https://peterfee.github.io/          <- recommended, cleanest URL
   Repo must be named exactly:  PETERFEE.github.io
   No config changes needed.

B) https://peterfee.github.io/portfolio/
   Repo can be named anything.
   You MUST uncomment the two "env:" lines in deploy.yml and set
   NEXT_PUBLIC_BASE_PATH to /<your-repo-name>, or every script and
   stylesheet will 404.

STEP 3 — push
-------------
  git init
  git add .
  git commit -m "Portfolio site"
  git branch -M main
  git remote add origin https://github.com/PETERFEE/PETERFEE.github.io.git
  git push -u origin main

STEP 4 — enable Pages (do not skip)
-----------------------------------
  On GitHub: your repo -> Settings -> Pages -> Source: "GitHub Actions"

  Pages defaults to serving from a branch, which ignores the workflow
  completely. Skipping this is the #1 reason a first deploy 404s.

Watch the build under the Actions tab. The live URL appears on the deploy
job when it finishes, usually 1-2 minutes.
