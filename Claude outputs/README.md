---

I like the part of the stack where software stops being an abstraction — RTL, firmware,
and the boards they run on. Most of what I build starts as a question about how something
actually behaves under load, then turns into a testbench or a scope trace that answers it.

I care about designs that are provably correct, not just ones that pass a smoke test.

## Selected work

| Project | What it is |
|---|---|
| **[AXI4-Stream Packet FIFO](https://peterfee.github.io/projects/packet-fifo-uvm/)** | Store-and-forward RTL with a UVM environment that predicts every dropped frame exactly. 5/5 injected bugs caught by mutation testing. |
| **[RTOS Monitoring Node](https://peterfee.github.io/projects/rtos-environmental-monitoring-node/)** | Five-task FreeRTOS firmware on STM32F103 streaming telemetry to an MQTT gateway. 93+ host-side unit tests. |
| **[AutoCar SLAM](https://peterfee.github.io/projects/autocar-slam/)** | A robot car that maps a room while it drives. ROS 2, RPLIDAR, live Foxglove visualisation. |
| **[DE10-Nano OpenCL](https://peterfee.github.io/projects/de10-nano-opencl-fpga-acceleration/)** | ARM-to-FPGA acceleration on Cyclone V — BSP, MMD layer, driver, and host application. |
| **[APB UART Verification](https://peterfee.github.io/projects/apb-uart-uvm-verification/)** | Two-agent UVM environment closing 100% functional coverage on a 16550-compatible core. |
| **[The Beauty and Math](https://peterfee.github.io/projects/the-beauty-and-math/)** | A parametric heart drawn from 2,500 particles of whatever you type. Runs in the browser. |
